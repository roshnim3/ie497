## Summary

This trace shows the complete lifecycle of a load instruction:
1. **Fetched** from instruction memory
2. **Decoded** to identify it as a load
3. **Renamed** with physical register allocation (P34)
4. **Dispatched** to memory reservation station
5. **Enqueued** in LSQ
6. **Address calculated** (base + offset)
7. **Issued** to memory FU (no dependencies)
8. **Cache accessed** and hit
9. **Result broadcast** on CDB
10. **PRF updated** with loaded value
11. **Committed** when it reaches ROB head
12. **Old physical register freed** back to freelist

Each step is clearly marked with timestamps and module identifiers, making it easy to trace the instruction's progress through the out-of-order pipeline.
